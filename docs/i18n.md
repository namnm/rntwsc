# I18n

Works on all variants: server, client, native. No extra setup needed.

## Usage

```tsx
import { useTranslation } from '#/i18n'

export const MyComponent = async () => {
  const t = await useTranslation('home')
  return <Text>{t('greeting')}</Text>
}
```

## Add a translation key

Add the key to each language file under `playground/app/src/i18n/labels/<lang>/<namespace>.json`:

```json
// en/home.json
{ "greeting": "Hello" }

// ja/home.json
{ "greeting": "Konnichiwa" }
```

## Add a namespace

1. Create `labels/<lang>/<namespace>.json` for each language.
2. Register in `playground/app/src/i18n/labels/index.ts`:

```ts
export const labels = {
  en: { home: enHome, settings: enSettings },
  ja: { home: jaHome, settings: jaSettings },
} as const
```

TypeScript infers valid `Namespace` values automatically from the `labels` shape.

## Add a language

Add an entry to `languages` in `playground/app/src/i18n/config.ts` and create the label files:

```ts
export const languages = [
  { locale: 'en-US', nativeName: 'English' },
  { locale: 'ja-JP', nativeName: 'Japanese' },
] as const
```

## Language switcher

Drop `I18nSwitcher` anywhere - renders locale links on web, pressable buttons on native:

```tsx
import { I18nSwitcher } from '#/i18n/i18n-switcher'

export const MyPage = async () => (
  <>
    <Content />
    <I18nSwitcher />
  </>
)
```

## Internals

Platform entry points in `packages/rn/core/i18n/`:

| File               | Used by           | How                                                                          |
| ------------------ | ----------------- | ---------------------------------------------------------------------------- |
| `index.tsx`        | Server components | Async hooks reading `x-i18n-locale` header, wrapped in `cache()`             |
| `index.client.tsx` | Client components | Sync hooks parsing locale from URL pathname                                  |
| `index.native.tsx` | React Native      | Hooks backed by i18next; exports `I18nProviderNative` and `initI18nNative()` |

I18n is initialized once at startup by `playground/app/src/polyfill/init-i18n.ts`:

```ts
import { initI18n } from '@/rn/core/i18n/config'
import { locales } from '#/i18n/config'
import { labels } from '#/i18n/labels'

initI18n(locales, labels)
```

This file is imported at the top of each platform's polyfill entry.

On web, switching locale navigates to a locale-prefixed URL; Next.js middleware sets the locale cookie. On native, i18next is called directly and the locale is persisted to AsyncStorage.

The framework exports `*Untyped` functions (`useTranslationUntyped`, `isValidLocaleUntyped`) so each app wraps them with strict `Locale`/`Namespace` types in `playground/app/src/i18n/index.ts` without coupling the core to any specific locale set.
